# Epic 5: Pathfinding Primitives (CA-4) — Phase 4 Opens

**Objective:** Deliver `setTraversalCosts` + `findPath` — A\* over the CSR adjacency graph inside the Worker with cooperative yielding — validating the Worker call harness that CA-5/6/8 build on.
**Scope:** Incorporates PRD §"Acceptance Criteria — Epic 5". Normative detail: ROADMAP §9 (CA-4, F-4.1, F-4.7).

**Entry gate:** `docs/audits/phase-3-audit.md` is `[PASS]` and merged to `main`. Do not start otherwise.

**Verifiable & Measurable Success Criteria:**

- **Latency:** a 500-sector path over a 10,000-sector graph resolves in < 2 ms in the Worker; P95 over the fixture's reachable pairs (`expectedCost !== null` — unreachable pairs are asserted separately for rejection type, not timed) < 2 ms on reference hardware.
- **Correctness:** returned `Uint16Array` paths are ordered start → end (`path[0] === start`, `path[path.length - 1] === end`; cameFrom reconstruction naturally yields end → start and must be reversed), contiguous in the adjacency graph, and cost-optimal against a reference Dijkstra check on ≥ 5 fixture pairs.
- **Failure semantics:** unreachable pairs (graph-disconnected, per Task 5.1) reject with `PathNotFoundError`. **Resolved (BDFL ruling, ROADMAP §9/§12.5 Hardening Sync):** `findPath` before `setTraversalCosts` has resolved at least once rejects with `CostsRequiredError` (canonical — already shipped in `src/errors.ts` by Phase 3 Epic 1 Task 1.2, archived at `docs/archive/v0.0.5/epics/epic-1-worker-bootstrap.md`; `SharedRegistryProxy`'s `ERROR` rehydration table already includes it, so `instanceof` assertions work across the Worker boundary). Rationale: explicit failure beats silently pathing on costs the consumer never supplied — the engine never invents game state (P-4), and hop-count paths would look plausible while being wrong for the consumer's game. Do not reuse `MappingRequiredError` here; its widened trigger covers mapping/aggregation preconditions only.
- **Isolation:** `SimulationClock` drift ≤ ±2 ms while a pathfinding burst runs.

## Tasks

### Task 5.1 — Fixture: `test/fixtures/pathfinding/grid-10k.json`

**PRD Reference:** §"Acceptance Criteria — Epic 5"; ROADMAP §9 CA-4 Fixture.

**Work:**

- Generate via a new script `test/fixtures/pathfinding/generate-grid-10k.js` (same convention as `test/fixtures/generate-fixtures.js`: committed alongside its output, re-runnable) a 100×100 grid graph: 10,000 nodes, 4-connected CSR arrays, `traversalCosts` (standard Array for JSON serialization) with values drawn from the range **1–255 (never 0)** via a hand-rolled deterministic PRNG implemented inline in the script (e.g. mulberry32, `seed=42`) — do not add a PRNG package dependency (none is currently installed); a small inline generator function guarantees the same script always reproduces identical bytes. Generate 50 start/end pairs (same seed stream) including at least one pair whose Dijkstra-optimal path contains ≥ 500 nodes. **Random pair selection cannot produce this pair:** the grid's Manhattan diameter is only 198 hops (199 nodes), and near-uniform random costs keep optimal paths within a small factor of Manhattan distance — so the generator must deterministically carve a low-cost (cost 1) serpentine corridor surrounded by max-cost (255) cells, place that pair at the corridor's ends, and confirm the ≥ 500-node count with the same reference Dijkstra that computes `expectedCost`.
- **Unreachability is produced by graph disconnection, not cost:** carve out one fully walled-off rectangular sub-region by omitting its boundary edges from the CSR adjacency arrays (no adjacency edges cross into/out of the region), and include at least one pair with one endpoint inside that region and one outside. `traversalCosts` never encodes impassability — finite edge costs can never make a connected node unreachable to A\*, so cost only affects path preference/optimality, and excluding 0 from the cost range keeps the A\* heuristic (Task 5.2) well-defined.
- Schema: `{width, height, adjacencyPointers, adjacencyNeighbors, traversalCosts, pairs: [{start, end, expectedCost|null}]}` — `expectedCost` computed by a reference Dijkstra in the generator; `null` marks unreachable. **Cost semantics (normative for both the generator and Task 5.2):** `traversalCosts` is per-node (length = node count, per ROADMAP §4), so define the cost of traversing edge a → b as `traversalCosts[b]` (the cost of entering b); a path's total cost is the sum over every node entered, the start node's own cost excluded. The generator's Dijkstra and the Worker A\* must share this exact definition or Task 5.4's cost verification will fail.

**Done when:** fixture committed; `node test/fixtures/pathfinding/generate-grid-10k.js` reproduces it byte-identically (seed determinism, same engine — this is a one-time committed artifact, not regenerated by test runs).

### Task 5.2 — `SpatialGraph` (Worker A\*)

**PRD Reference:** §"New modules"; ROADMAP §9 CA-4.

**Work:**

- Create `src/worker/SpatialGraph.ts`: constructed from `adjacencyPointers`/`adjacencyNeighbors` + `traversalCosts` + `centroids` (`Int16Array`, `[x, y]` per node — the heuristic below requires them; in the Worker they come from the BOOTSTRAP state (`getWorkerState().centroids`, present in `BootstrapPayload`), and for the grid fixture — whose JSON carries no centroid array — they are derived as `x = i % width`, `y = (i / width) | 0`); `findPath(start, end): Promise<Uint16Array>` — A\* with binary-heap open set over typed arrays (scores in preallocated `Float32Array`, cameFrom in `Uint16Array` using `0xFFFF` as the "no predecessor" sentinel for `start`, per §12.3; zero per-node object allocation, PR-3), heuristic `h(n) = euclideanDistance(centroid(n), centroid(goal)) * minPossibleCost` — **multiply, never divide** (dividing by cost would divide-by-zero if a 0 cost ever appeared; Task 5.1 excludes 0 from the fixture's cost range for exactly this reason). Admissibility requires `h(n) ≤` true remaining cost, which constrains the multiplier by **distance, not just cost**: the multiplier must be ≤ `min over all edges (edgeCost / centroidDistance(a, b))`. On the unit-spaced grid fixture (adjacent centroids exactly 1 apart, edge costs ≥ 1) a multiplier of `1` satisfies this; on a real map it does not — adjacent centroids are many pixels apart (e.g. a 10-hop route of cost-1 edges spanning 2,000 px has true cost 10 but `h = 2,000`, a 200× overestimate → non-optimal paths) — so compute the multiplier as `minEdgeCost / maxAdjacentCentroidDistance` in one O(E) pass at graph-build time (if `maxAdjacentCentroidDistance` is 0, clamp the multiplier to 0 to prevent `Infinity` breaking the heuristic).
- `await yieldIfNeeded(state)` inside the expansion loop (≤ 8 ms slices).
- Throws `PathNotFoundError` when the open set empties.

**Done when:** Node-mode unit tests over small hand-built graphs pass (shortest path; tie determinism — pick and document an explicit tie-break, e.g. lower node id on equal f-score, since raw binary-heap ordering is not stable; unreachable → `PathNotFoundError`); zero DOM/Three.js imports (`git grep -E "three|document|window" src/worker/SpatialGraph.ts` empty).

### Task 5.3 — Public API: `setTraversalCosts` + `findPath`

**PRD Reference:** §"Public API delta".

**Work:**

- Worker handlers: `setTraversalCosts` (receive Transferable `Uint8Array`, length must equal `sectorCount` — on mismatch reject via the standard `ERROR` message path without building the graph; otherwise store and (re)build `SpatialGraph`), `findPath` (delegate; validate both ids are integers `< sectorCount` before searching — out-of-range ids would silently index past the preallocated scratch arrays; `RESULT` carries the path `Uint16Array` back to Main via standard structured-clone `postMessage` — PRD §9 CA-4 does not mandate a transfer list for the path array, and a transfer assertion would be unfalsifiable from Main anyway).
- **Serialize Worker-side search execution:** `findPath` awaits `yieldIfNeeded`, so the Worker processes further `CALL` messages mid-search; a second concurrent `findPath` (or a `setTraversalCosts` rebuild) would interleave on `SpatialGraph`'s shared preallocated scratch arrays and corrupt both searches. Chain `findPath`/`setTraversalCosts` execution FIFO in the Worker (a simple promise chain); callers still receive independent Promises.
- `MapEngine.setTraversalCosts(costs: Uint8Array): Promise<void>` — transfers ownership by including `costs.buffer` itself (the caller's actual `ArrayBuffer`, never a copy/slice of it) in the `postMessage` transfer list; reject with a standard Error if `costs.byteOffset !== 0 || costs.byteLength !== costs.buffer.byteLength` to prevent detaching unrelated consumer memory if passed a sub-view; document that replacement needs a fresh allocation, §4. `MapEngine.findPath(startId: number, endId: number): Promise<Uint16Array>`.
- Both are in-flight-registered via `SharedRegistryProxy` so the Phase 3 lifecycle invalidation (`rejectAll` in `src/worker/SharedRegistryProxy.ts`; archived spec: `docs/archive/v0.0.5/epics/epic-3-registry-proxy.md`) rejects them with `MapInvalidatedError` on `loadMap`/`dispose`.
- Enforce the `findPath`-before-`setTraversalCosts` precondition on Main (by tracking resolution state): reject with `CostsRequiredError` (Worker-side enforcement fails this if `findPath` is called while `setTraversalCosts` is in-flight); document the behavior in TSDoc, and add a test asserting the rejection type.
- Update `example/src/controller.ts`: click two sectors → path computed and visualized (e.g., palette highlight of path sectors).

**Done when:** browser-mode integration test loads a small real map through the standard `loadMap()` pipeline (**not** `grid-10k.json` — that fixture is a synthetic CSR-only JSON with no corresponding bitmap and cannot be loaded via `loadMap()`; see Task 5.4 for how the 10k fixture is actually exercised) and round-trips a path through the real Worker; `costs.byteLength === 0` on Main post-call (this only holds if `costs.buffer` was the transferred buffer, not a copy — see above); lifecycle rejection test extended to `findPath`.

### Task 5.4 — Performance gate + drift assertion (F-4.7)

**PRD Reference:** §"Acceptance Criteria — Epic 5".

**Work:**

- Perf spec (`*.gl.spec.ts` naming per the F-2.7 perf-test split, Playwright/real Chromium): `grid-10k.json` has no corresponding bitmap (it is a synthetic CSR fixture), so this spec does **not** go through `MapEngine.loadMap()`/`BOOTSTRAP` — and it cannot use the real Worker entry either: `src/worker/index.ts` only accepts `BOOTSTRAP` (which requires the nine bitmap-derived buffers, `pixelIndices` included) and has no message that injects a raw CSR graph. Run the 50 fixture pairs through `findPath` (unreachable pairs reject — catch and assert `PathNotFoundError`; exclude them from the latency sample), assert P95 over the reachable pairs < 2 ms and the ≥ 500-node pair < 2 ms (reference hardware; 5.0× CI tolerance).

- Verify path costs equal the fixture's reference `expectedCost` values.
